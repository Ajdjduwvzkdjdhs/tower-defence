# lidar-tracker2.1 — URG 版の落氷検知

`tools/lidar-tracker2`（Hokuyo URG + C++）のセンサ側はそのまま使い、検出部だけを
`tools/lidar-tracker`（YDLidar T-mini Plus + Python）の落氷検知と同じ数え方に
差し替えたもの。**セクタを通った落氷の回数と点数を数える。**

```
./build.sh          ビルド（変更があったときだけ）
./urg_check         疎通確認（GUI なし）
./a.out             実行           （-s /dev/tty.usbmodemXXX でポート上書き）
./urg_reset.sh      ハングしたときの復帰
```

操作は `r`（カウンタを 0 に戻す）、`m`（simple / background を切り替え）、`ESC`（終了）。
起動した時点から数え始める（`r` はリセット専用で、押すまで数えないようにはしていない）。

## lidar-tracker2 から何を変えたか

`lidar-tracker2` は点群を OpenGL で描いてラスタ画像にし、`erode`/`dilate` と
`findContours` で塊を見つけて重心（足の設置位置）を出す画像処理ベースのツールだった。
落氷を数えるにはこれでは足りない:

- 塊の位置は出るが、時間方向の処理が無いので「何回落ちたか」を数えられない。
- 静止物（壁・機体・氷の山）が毎フレーム同じ塊として出続けるので、落氷と区別できない。

そこで検出部を丸ごと差し替えた。OpenGL / GLUT は検出にも描画にも要らなくなったので
落とし（`build.sh` からもリンクを外した）、表示は OpenCV だけで描いている。

| | lidar-tracker2 | lidar-tracker2.1（これ） |
|---|---|---|
| 空間の扱い | 直交座標へ変換しラスタ画像化 | 極座標のまま角度ビン配列 |
| 関心領域 | 矩形（描画範囲）＋下限 50mm | 同心円 `RANGE_MIN..RANGE_MAX` ＋扇形セクタ |
| 点のグルーピング | erode/dilate + findContours | しない（セクタ内の点数を数える） |
| 時間方向 | なし（毎フレーム独立） | 背景学習＋立ち上がり検出＋猶予 |
| 出力 | 塊の重心座標 | 検出回数（hits）と点数（pts） |
| 依存 | OpenCV + OpenGL/GLUT | OpenCV のみ |

## 数え方（lidar-tracker と同じ規則）

1. 全周を 1° 刻みの角度ビンに分け、1 スキャンぶんの点を表示角（0 度＝画面上、時計回り）で
   ビンに入れる。
2. `RANGE_MIN..RANGE_MAX` の同心円の外と、センサのエラー値は捨てる。
3. 計測セクタに入った有効点だけを数の対象にする。
4. 「有り／無し」を判定する。
   - `simple`: セクタ内に有効点があれば「有り」（既定）。
   - `background`: 起動直後にビンごとの静止背景（距離の中位値）を学習し、そこから
     `COUNT_FOREGROUND_MARGIN_MM` 以上手前を通った点だけを「有り」とする。セクタに壁や
     機体が写っていて `simple` では hits が 1 で張り付くときに使う。図の灰色の点線が
     そのしきい線。
5. 「無し → 有り」の立ち上がりだけを 1 回と数える。点滅で 1 回が 2 回に割れないよう、
   `COUNT_RELEASE_SEC` の間ずっと「無し」が続くまでは同じ検出が続いているとみなす。

左の欄に出る数字は lidar-tracker と同じ意味:

- `hits` — 立ち上がりの回数（＝落ちた回数）
- `pts` — 「有り」と数えた点の累計（1 回の検出がどれだけ濃く写ったか）
- `now` — 直近 1 スキャンで「有り」と数えた点数。hits が増えないときに、点が入って
  いないのか（`now` も 0）、入っているのに立ち上がらないのか（`now` > 0）を切り分ける

立ち上がった瞬間は標準出力にも `hit 3  (5 pts, total 41 pts)` の形で出る。

## lidar-tracker との違い（センサの性質からくるもの）

- **「1 回転」が「1 スキャン」になる。** URG は 360 度回らず前方 ±90 度の往復スキャンなので、
  数え方の規則はそのままで単位だけが変わる。見えない後方は図に灰色で塗ってある。
  セクタの既定も、あちらの 225-315 度（後方）ではなく正面 ±45 度（315-45）にしてある。
- **猶予と学習の長さは秒で持ち、スキャン周期は実測する。** URG は機種でスキャン周期が
  違うので、起動時に 25 スキャン（約 0.6 秒）ぶんの所要時間を測り、そこから秒をスキャン数へ
  直す。`urg.scan_usec()`（センサが PP で申告する公称値）を使わないのは、カタログ値や
  実際の回転数と食い違うことがあるため。手元の UBG-04LX-F01 はカタログ 28ms/scan に対し、
  公称・実測（壁時計とセンサのタイムスタンプの両方）とも 25.0ms/scan だった。
  タイトルに出るのは実測値（`measured`）で、公称値との食い違いは起動時に標準出力へ出る。
  既定値は lidar-tracker の 2 回転 / 20 回転（10Hz 換算で 0.2 秒 / 2 秒）と同じ時間。
- **Intensity と干渉フラグ 0x03 は無い。** どちらも YDLidar SDK 固有の値で URG の Distance
  モードには存在しないので、強度による色分けと太陽光ノイズのカウンタは移植していない。
- **接続設定はコード側。** lidar-tracker の `config.toml` にあたるものは無く、接続先は
  `Connection_information.cpp`（既定 `/dev/tty.usbmodem101`）か実行時の `-s` オプション、
  検出パラメータは `mainD.cpp` 冒頭の「設定」定数で変える。
- **1 台のみ。** lidar-tracker のような複数台の同時表示はしていない。

## 現物合わせで触るところ（`mainD.cpp` 冒頭の「設定」）

| 定数 | 既定 | 何を決めるか |
|---|---|---|
| `RANGE_MIN_CM` / `RANGE_MAX_CM` | 0 / 80 | 関心円。壁や周囲の人を落とす主要なノブ |
| `COUNT_SECTOR_START_DEG` / `_END_DEG` | 315 / 45 | 数える扇形（0 度またぎ可） |
| `COUNT_RELEASE_SEC` | 0.2 | 何秒「無し」が続いたら次を新しい 1 回と数えるか |
| `COUNT_BACKGROUND_SEC` | 2.0 | background の背景学習にかける時間 |
| `COUNT_FOREGROUND_MARGIN_MM` | 100 | 背景より何 mm 手前なら「前を通った」か |
| `ANGLE_OFFSET_DEG` | 0 | センサ正面を画面上のどこに向けるか |
| `SCAN_ANGLE_DEG` | 180 | URG のスキャン角度範囲 |

セクタがセンサの視野（正面 ±90 度）から外れていると、起動時に警告を出す。

## 注意

- 起動直後の約 0.6 秒はスキャン周期の実測に使うので、数え始めはそのぶん遅れる
  （`MEASURE_WARMUP_SCANS` / `MEASURE_SAMPLE_SCANS`）。
- 数えるのは毎スキャン、描くのは `DRAW_INTERVAL_MS`（既定 33ms）ごと。描画を間引いても
  カウントは取りこぼさない。
- **計測を始めたあとにセンサへ問い合わせを送らないこと。** `product_type()` /
  `firmware_version()` / `serial_id()` / `status()` / `state()` は「VV」などのコマンドを
  送って応答を読むので、計測データが流れている最中に呼ぶと応答がストリームと混ざる。
  戻り値が `receive error.` になるだけでなく、以後の `get_distance()` が
  `no response` で失敗し続ける。タイトルに出す情報は `start_measurement()` の前に
  取ってある（`min_distance()` / `scan_usec()` は open 時に読んだ値を返すだけなので安全）。
- 終了は `ESC` か `Ctrl-C` で。どちらでも `stop_measurement()` が走る。強制終了して
  センサがデータを流しっぱなしになると次回の `urg.open()` がハングするので、そのときは
  `./urg_reset.sh` を実行してから起動し直す。
